## Đính chính phân loại A1

Đọc thân 38 function "A1 admin-only đang hở": **22 cái đã có guard `has_role(auth.uid(), 'admin')` đúng** (`log_founder_admin_action`, `set_wallet_kill_switch`, `set_wallet_strict_mode`, `tt_*`, `get_unified_admin_stats`, `get_founder_*`, `live_replay_*`, `get_pplp_admin_stats`, …) — nhãn "hở" là **sai**. Số thật sự cần xử lý nhỏ hơn nhiều, chia 2 đợt:

- **Đợt 1 (đã làm — P0):** 6 cái guard bằng `p_admin_id` do client truyền. Trong đó 5 cái xử lý ở migration này; `run_financial_reconciliation` (thân dài, chạm dữ liệu tài chính) tách sang đợt 2.
- **Đợt 2 (còn treo):** `run_financial_reconciliation` + nhóm không có guard nào (`get_all_claim_history`, `get_banned_user_claims`, `get_user_directory_summary`, `get_user_directory_totals`, `get_content_users_by_period_vn`, `get_user_mint_stats`, `get_attester_dashboard_stats`, `get_attester_mint_requests`).

## Lỗ hổng đã đóng (P0)

| Function | Khai thác trước đây |
|---|---|
| `ban_user_permanently(p_admin_id, …)` | User thường truyền UUID của một admin bất kỳ → **ban vĩnh viễn user khác** + blacklist ví + reject mint request |
| `unban_user(p_admin_id, …)` | Mở khóa tài khoản đã bị ban, xoá ví khỏi blacklist |
| `batch_ban_ghost_users(user_ids, admin_id)` | Ban hàng loạt |
| `get_user_emails_for_admin(p_admin_id)` | **Đọc toàn bộ email `auth.users`** |
| `get_qualified_reward_users(p_admin_id)` | Đọc danh sách ứng viên thưởng + ví + reward_status |

UUID admin không phải bí mật (hiển thị công khai qua `profiles.id`), nên đây là khai thác thực tế, không lý thuyết.

## Cách sửa

- Giữ nguyên **signature** → không phải sửa 19 call site FE.
- `v_actor uuid := auth.uid()`; chặn `NULL` (`Authentication required`), chặn `NOT has_role(v_actor,'admin')`.
- Audit log ghi **actor thật**; `p_admin_id`/`admin_id` do client khai báo chỉ lưu trong `details.claimed_admin_id` để đối chiếu.
- `REVOKE ALL … FROM PUBLIC, anon` (bài học: thiếu `PUBLIC` = REVOKE vô hiệu) + `GRANT EXECUTE … TO authenticated, service_role`.

## Evidence
