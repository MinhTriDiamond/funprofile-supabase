## 2. Nhóm A — không REVOKE, đề xuất thêm guard

### 2.1 `recalculate_user_financial(p_user_id, p_client_id, p_admin_id)`
FE gọi **từ admin panel** (`FinancialTab.tsx`), truyền `p_user_id` của **user khác** + `p_admin_id` do client tự khai ⇒ **không** thể dùng guard `p_user_id = auth.uid()`. Guard đúng là kiểm tra role admin, và **bỏ tin cậy `p_admin_id`**:

```sql
-- chèn ngay đầu thân function (đề xuất, CTO duyệt trước khi chạy)
IF NOT public.has_role(auth.uid(), 'admin') THEN
  RAISE EXCEPTION 'FORBIDDEN_ADMIN_ONLY' USING ERRCODE = '42501';
END IF;
-- và dùng auth.uid() thay cho p_admin_id khi ghi audit
```
Không phá FE: admin thật vẫn pass; `p_admin_id` giữ trong signature để không đổi call site.

### 2.2 `check_login_method(p_email)`
Bản chất **phải gọi được khi chưa đăng nhập** (dùng để gợi ý "tài khoản này chỉ có OTP" sau khi sai mật khẩu) ⇒ guard `auth.uid()` là bất khả thi, đây là ca **CTO cần thiết kế lại**, không phải vá 1 dòng. 2 hướng:

- **B1 (khuyến nghị)**: chuyển sang edge function `auth-login-method` có rate-limit theo IP (dùng `check_rate_limit` đã có) + trả về **thông tin tối giản** (chỉ `has_password`, không xác nhận `exists`), rồi REVOKE RPC.
- **B2 (tối thiểu)**: giữ RPC nhưng thêm rate-limit nội bộ theo `p_email` + luôn trả `exists: true` để **không** cho phép email enumeration.

`get_auth_user_id_by_email` **không** vướng chuyện này (FE=0) nên đi thẳng nhóm B.

## 3. Đường ghi `profiles.wallet_address` — guard đã đủ (mục CHƯA VERIFY của lượt trước)

Ngoài `process_wallet_change`, đường ghi trực tiếp `UPDATE public.profiles` bị chặn bởi:

| Lớp | Nội dung | Kết luận |
|---|---|---|
| RLS UPDATE | `Users can update their own profile` → `auth.uid() = id`; `Admins can update any profile` → `has_role(auth.uid(),'admin')` | **Có guard `auth.uid()` đúng.** Không có policy nào cho phép sửa hàng của người khác |
| `trg_prevent_wallet_hijack` | chặn gán địa chỉ đã thuộc user khác (so sánh lower() trên 4 cột ví) | chống chiếm ví chéo |
| `trg_normalize_wallet_addresses` | lowercase mọi cột ví | đúng chuẩn AGENTS.md §6 |
| `trg_audit_wallet_changes` + `trg_wallet_writer_guard` | ghi `wallet_writer_audit` (kèm `auth.uid()`) mọi lần đổi ví | có dấu vết |
| `trg_wallet_kill_switch` | `app_settings.wallet_updates_enabled` = `true` hiện tại | khoá khẩn cấp sẵn sàng |

⚠ Một điểm cần CTO biết: `wallet_writes_strict_mode = **false**` ⇒ `fn_wallet_writer_guard` hiện **chỉ audit, không chặn** writer lạ (whitelist 8 tag đã cấu hình nhưng không enforce).

**Kết luận mức độ cuối của Đ9 với `process_wallet_change`:** vẫn **P0**, vì RPC này là `SECURITY DEFINER` nên **đi vòng qua RLS** — bất kỳ ai có publishable key đổi được ví của user tuỳ ý, và `p_reason='admin'` tự bật đường override (bỏ cooldown/feature flag). Các trigger còn lại chỉ giới hạn thiệt hại (không chiếm được ví đã thuộc người khác, có audit), **không** ngăn được hành vi.

## 4. Câu lệnh containment đề xuất (nhóm B của Đ8+Đ9) — chờ CTO duyệt

Chỉ đổi **permission**, không đụng logic/dữ liệu. Rollback = `GRANT EXECUTE ... TO authenticated;`.

```sql
-- ==== Đ8 ====
REVOKE EXECUTE ON FUNCTION public.cron_unschedule_by_name(text)          FROM PUBLIC, anon, authenticated;
REVOKE EXECUTE ON FUNCTION public.get_auth_user_id_by_email(text)        FROM PUBLIC, anon, authenticated;

-- ==== Đ9 — ghi state kinh tế cho user tuỳ ý ====
REVOKE EXECUTE ON FUNCTION public.process_wallet_change(uuid, text, text, text, text)  FROM PUBLIC, anon, authenticated;
REVOKE EXECUTE ON FUNCTION public.apply_pet_xp_grant(uuid, integer, text)              FROM PUBLIC, anon, authenticated;
REVOKE EXECUTE ON FUNCTION public.apply_pet_event(uuid, text)                          FROM PUBLIC, anon, authenticated;
REVOKE EXECUTE ON FUNCTION public.mystery_box_grant(uuid, text, text, text)             FROM PUBLIC, anon, authenticated;
REVOKE EXECUTE ON FUNCTION public.mystery_box_finalize_order(uuid, text, text)          FROM PUBLIC, anon, authenticated;
REVOKE EXECUTE ON FUNCTION public.mystery_box_fail_order(uuid, text)                    FROM PUBLIC, anon, authenticated;
REVOKE EXECUTE ON FUNCTION public.pet_shop_finalize_order(uuid, text, text)             FROM PUBLIC, anon, authenticated;
REVOKE EXECUTE ON FUNCTION public.pet_shop_fail_order(uuid, text)                       FROM PUBLIC, anon, authenticated;
REVOKE EXECUTE ON FUNCTION public.quest_set_progress(uuid, text, integer)               FROM PUBLIC, anon, authenticated;
REVOKE EXECUTE ON FUNCTION public.quest_record_progress(uuid, text, integer)            FROM PUBLIC, anon, authenticated;
REVOKE EXECUTE ON FUNCTION public.check_user_cap_and_update(uuid, text, numeric)        FROM PUBLIC, anon, authenticated;
REVOKE EXECUTE ON FUNCTION public.unlock_wallet_reward(uuid)                            FROM PUBLIC, anon, authenticated;
REVOKE EXECUTE ON FUNCTION public.get_next_nonce(uuid)                                  FROM PUBLIC, anon, authenticated;
REVOKE EXECUTE ON FUNCTION public.pet_risk_recompute(uuid)                              FROM PUBLIC, anon, authenticated;
```

> Trước khi chạy: lấy **signature chính xác** bằng
> `select 'REVOKE EXECUTE ON FUNCTION public.'||proname||'('||pg_get_function_identity_arguments(oid)||') FROM PUBLIC, anon, authenticated;' from pg_proc where proname in (...);`
> (các arg-list phía trên là ghi theo tên đọc từ code — phải khớp tuyệt đối, nếu lệch câu lệnh sẽ báo `function does not exist` chứ không revoke sai cái khác).

Sau khi chạy, verify:
```sql
select proname, has_function_privilege('anon',oid,'EXECUTE'), has_function_privilege('authenticated',oid,'EXECUTE')
from pg_proc where proname in ('cron_unschedule_by_name','process_wallet_change','mystery_box_grant','quest_set_progress');
-- kỳ vọng: f | f
```
