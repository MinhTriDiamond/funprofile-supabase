# Mục 5 — 3 điều kiện tiên quyết trước khi bật `wallet_writes_strict_mode` (2026-08-16)

Số liệu thật tại thời điểm viết:

| Chỉ số | Giá trị |
|---|---|
| `wallet_writes_strict_mode` | `false` (monitor) |
| `wallet_writers_allowed` | 8 tag: `btc-wallet-audit`, `connect-external-wallet`, `disconnect-external-wallet`, `identity-link-manage`, `admin-wallet-restore`, `custodial-wallet-create`, `auth-wallet-link`, `manual-admin-update` |
| `wallet_writer_audit` tổng dòng | **465** |
| Trong đó `writer_tag IS NULL` | **465 (100%)** |
| 7 ngày gần nhất | 31 dòng |
| Khoảng thời gian audit | 2026-06-11 → 2026-08-15 (≈ 65 ngày) |

Trigger `fn_wallet_writer_guard()` đọc tag bằng `current_setting('app.wallet_writer', true)`; nếu tag NULL hoặc không nằm trong whitelist thì `v_block := v_strict AND NOT v_is_allowed`. ⇒ Bật strict mode hôm nay sẽ **chặn 100% lượt ghi ví**, kể cả flow hợp lệ.

## Điều kiện 1 — Mọi writer hợp lệ phải `SET LOCAL app.wallet_writer` trước UPDATE

- **Trạng thái: CHƯA ĐẠT** (0/465 dòng có tag).
- Cần làm: với từng edge function ghi vào `profiles.{wallet_address, public_wallet_address, external_wallet_address, btc_address}`, thêm `SET LOCAL app.wallet_writer = '<tag>'` trong cùng transaction với UPDATE. Tag phải trùng 1 trong 8 giá trị whitelist; nếu phát sinh writer mới thì cập nhật JSON `wallet_writers_allowed` trước.
- Khối lượng: cần liệt kê chính xác danh sách writer từ dữ liệu audit (`application_name`, `changed_by`) rồi map 1-1 sang edge function.

## Điều kiện 2 — Đường FE user tự đổi ví phải có tag

- **Trạng thái: CHƯA ĐẠT.** Theo điều tra trước, ~97% lượt ghi là **self-edit** (user tự đổi ví trong trang cá nhân) đi trực tiếp qua PostgREST, không qua edge function ⇒ không có chỗ nào đặt tag.
- Hai lựa chọn (CTO chọn 1):
  - (a) Chuyển đường tự đổi ví qua một edge function có tag riêng (`self-service-profile`) — an toàn nhất, nhưng phải sửa FE.
  - (b) Thêm tag `self-service-profile` vào whitelist và đặt tag bằng RLS-safe helper/`pre-request` hook của PostgREST — nhanh hơn, nhưng độ tin cậy thấp hơn.

## Điều kiện 3 — Chạy audit-only ≥ 7 ngày với `is_allowed = true` gần 100%

- **Trạng thái: CHƯA ĐẠT** (chưa bắt đầu vì điều kiện 1+2 chưa xong; hiện `is_allowed` = false toàn bộ).
- Tiêu chí thoát: 7 ngày liên tục, tỉ lệ dòng `is_allowed = true` ≥ 99%, và 0 dòng `(untagged)` phát sinh từ `application_name = postgrest`.
- Chỉ sau khi đạt mới bật strict mode qua Admin UI (RPC `set_wallet_strict_mode`, bắt buộc nhập lý do), rồi theo dõi 1 giờ đầu; nếu có `blocked = true` cho writer hợp lệ thì tắt ngay.

## Ước lượng để CTO xếp lịch

| Bước | Khối lượng | Thời gian chờ |
|---|---|---|

| ĐK2 — quyết đường self-edit (a) hay (b) | cần CTO chốt trước khi code | — |
