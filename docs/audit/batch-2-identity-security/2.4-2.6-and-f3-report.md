### 6.4 Kết luận cho CTO (chưa quyết)

- Bật `strict_mode = true` **ngay lúc này = false positive 100 %**, sẽ chặn cả FE tự đổi ví lẫn mọi edge function đã whitelist. **Tuyệt đối không bật trước khi làm bước dưới.**
- Điều kiện tiên quyết nếu muốn bật: (a) mọi writer hợp lệ phải `SET LOCAL app.wallet_writer = '<tag>'` trước khi UPDATE; (b) đường FE tự đổi ví phải được chuyển qua edge function có tag, hoặc thêm tag `self-service-profile` vào whitelist; (c) chạy lại audit-only ≥ 7 ngày, xác nhận `is_allowed = true` gần 100 % rồi mới bật.
- Tin tốt: trong 63 ngày **không có một trường hợp nào đổi ví của user khác** (0/461) ⇒ RLS + `prevent_wallet_hijack` đang giữ đúng ranh giới; writer-guard hiện là lớp phòng thủ dự phòng, chưa cần khẩn.

## 8. THỰC THI (2026-08-14) — REVOKE nhóm B, phần 28 function mutate state

### 8.1 Phát hiện mới quan trọng: ACL `PUBLIC` (`=X`) làm REVOKE đợt đầu vô hiệu

Migration đợt 1 chỉ `REVOKE ... FROM anon, authenticated` ⇒ **19/28 function vẫn gọi được**, vì ACL thật là:

```
approve_user_reward|{=X/postgres,postgres=X/postgres,service_role=X/postgres,...}
                     ^^^ =X  = cấp cho PUBLIC (mọi role, gồm anon+authenticated)
```

Phải bổ sung `REVOKE ALL ON FUNCTION ... FROM PUBLIC`. Sau migration đợt 2: `still_open = 0`.
→ **Bài học bắt buộc cho mọi REVOKE về sau: luôn revoke cả `PUBLIC`, không chỉ `anon, authenticated`.**
Đối chiếu linter: **408 → 370 issue** (giảm đúng 38 warning `anon_security_definer_function_executable`).

### 8.2 Đính chính phân loại: 10 function bị xếp nhóm B SAI (FE CÓ gọi)
